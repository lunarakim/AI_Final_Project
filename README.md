# StatMind AI: AI-Powered Marketing Analytics Agent

Course project for **CSS4007 Artificial Intelligence** (Narxoz University, section CSS4007-ENG-5).
Team: Akim Lunara, Rustamova Radmila, Doshchanova Tomiris.

StatMind AI lets a small e-commerce owner or marketing manager upload campaign data and ask questions in plain English or Russian. An LLM agent decides which analysis to run, calls tested Python tools, and answers with verified numbers, charts and a short explanation. It says so when the data cannot answer a question instead of inventing values.

## The problem

Small e-commerce businesses run campaigns across several marketing channels but often have no dedicated analyst. Spreadsheet reports make it hard to compare channels and spot wasted ad spend, and a general chatbot asked to analyse a table tends to invent numbers. Our users need reliable, actionable insights without statistical or programming skills.

## What the product does

- Upload a campaign file (CSV or XLSX) and get automatic schema and data-quality checks.
- Ask questions such as:
  - "Which channel had the highest ROAS last month?"
  - "Why did ROAS drop in week 3?"
  - "Which campaign has the worst CPA?"
- Get an answer with the numbers, a chart and the tools that were used.
- Supported metrics: CTR, CPC, conversion rate, CPA, ROAS; comparisons across channels, campaigns and periods; trends and anomaly detection.
- Ambiguous request: the agent asks a clarifying question. Question the data cannot answer: the agent says so.

## How it works

The AI feature is a **tool-use agent loop** built on the Gemini API:

1. The agent reads the question and plans the analysis.
2. It calls approved Python tools (inspect data, calculate KPIs, compare channels/campaigns/periods, analyse trends, detect anomalies).
3. It reads each tool result and can chain several calls (for example: find the drop, split it by channel, compare periods).
4. It writes the final answer from the tool outputs.

All calculations are done by Python code, not by the LLM. The agent cannot execute arbitrary code: it can only call the tools listed in the tool registry, which are validated against JSON schemas.

```
User question -> Streamlit app -> Agent (Gemini function calling)
                                     |        ^
                                     v        |
                              Tool dispatcher (validated calls)
                                     |
                                     v
                         Analytics engine (pandas) -> numbers, charts
```

## Evaluation

We measure the AI feature on **30 fixed test questions** in five groups: KPI calculation, channel/period comparison, trends, multi-step diagnosis, and unanswerable or ambiguous questions (about 5 of them in Russian). Reference answers come from ground truth planted in the synthetic data and are prepared by a team member who did not write the tools. A small public marketing dataset is used as an independent test.

| Metric | Target | Result |
|---|---|---|
| Tool-selection accuracy | ≥ 85% | _to be filled_ |
| Numerical accuracy (values within 1% relative error) | ≥ 95% | _to be filled_ |
| Faithfulness (numbers in the explanation match tool output) | ≥ 95% | _to be filled_ |
| Correct clarification or refusal on unanswerable questions | ≥ 80% | _to be filled_ |
| Explanation quality (5-point rubric, two raters) | average ≥ 4 / 5 | _to be filled_ |

**Baseline:** the same Gemini model without tools, answering from a text version of the table. We report the gap on every metric.

The rubric scores an explanation on four points: correct, complete, clear, no unsupported claims.

## Data

- **Synthetic dataset** (generated by a script with a fixed seed): date, campaign, channel, impressions, clicks, ad spend, conversions, revenue, covering several months. It contains planted known answers (best channel, a ROAS drop, anomalies) that serve as ground truth.
- **Public dataset for the independent test:** _name, source and licence to be added_.
- No personal customer data and no live ad-platform integration.


Evaluation responses are cached, so repeated runs do not use extra API quota.

## LLM provider and limits

The product uses the Gemini API (Google AI Studio free tier) behind a swappable LLM client. If free-tier quotas block work, the provider can be switched to OpenRouter or a local Ollama model through configuration. API keys are read only from environment variables.

## How we built it (agentic development)

The project is built with agentic coding tools:

- **OpenCode** (free, open source) with free coding models via OpenRouter for day-to-day development.
- **Claude Code** (paid) for planning and hard tasks.
- **GitHub Copilot Free** (agent mode) as a backup when quotas run out.

The process is documented in the repository: `PLAN.md` (written before the code), `AGENTS.md` (instructions given to the agents), `agent-logs/` (key sessions), `DECISIONS.md` (important decisions, including where the agent was wrong) and `REFLECTION.md`. Any tool switch is recorded in `DECISIONS.md`.

## Limitations

- The agent is only as reliable as its tool set: questions outside the supported analyses are refused or answered with a clarifying question.
- Results on synthetic data may be easier than on real campaign exports; the public dataset test is meant to show the gap.
- The Gemini free tier has request limits, so large evaluation runs are cached and executed in batches.
